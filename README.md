# Card Spend Audit

What if Oklahoma's state purchase cards could say no at the register? This project replays two
years of the state's real, public card transactions (843,229 of them, $366.5M of purchases, 119 agencies)
through card controls that decide at the moment of the swipe, checks the same history with
after-the-fact rules, and has an AI reviewer work the biggest flags. Every claim is measured
against misuse planted in the data on purpose.

- **WRITEUP.md**: the story and the findings.
- **REPORT.md**: every number, generated by the pipeline.
- **The site**: an interactive version with a strictness dial and a case-review inbox.

## See the site (no setup beyond Python)

You need [uv](https://docs.astral.sh/uv/getting-started/installation/) once:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Then, in this folder:

```bash
uv sync
```

```bash
uv run python -m spendaudit serve
```

Open http://localhost:8000. Press Ctrl+C in the terminal to stop.

## Rebuild every number from the real data

The first time, this downloads the 24 monthly files from data.ok.gov (about 170 MB; about 4
minutes). It then reruns everything except the AI reviewer, whose answers are cached in
`out/cases.json`:

```bash
uv run python -m spendaudit all
```

After the download it takes under a minute. It rewrites `DATA.md`, `REPORT.md`,
`WRITEUP.md` and the site data in `web/public/data/`. To refresh the site itself after that, you
need Node (see "Changing the site" below).

### Rerun the AI reviewer

The reviewer runs on your Claude plan through Claude Code, not an API key. You need Claude Code
installed and signed in (`claude` in a terminal should start it). Then:

```bash
uv run python -m spendaudit investigate
```

```bash
uv run python -m spendaudit export
```

Only cases whose details changed are rerun. Each takes 10 to 20 seconds; 50 cases cost about
$2.50 at API prices, which your plan covers.

## Steps one at a time

| Command | What it does |
|---|---|
| `uv run python -m spendaudit build` | Download (once), check the data, clean merchant names, write `DATA.md` |
| `uv run python -m spendaudit rules` | Run the four rule checks on the real data |
| `uv run python -m spendaudit plant` | Plant misuse over 5 seeds and measure what the rules catch |
| `uv run python -m spendaudit replay` | Replay history with swipe-time controls at 21 strictness settings |
| `uv run python -m spendaudit investigate` | AI reviewer on 50 cases (uses your Claude plan) |
| `uv run python -m spendaudit export` | Write the site data, `REPORT.md` and `WRITEUP.md` |
| `uv run python -m spendaudit serve` | Serve the built site at http://localhost:8000 |

## Changing the site

The site lives in `web/` (React, Vite, Tailwind). The built copy in `web/dist` is committed, so
you only need Node to change it:

```bash
cd web && npm install && npm run build
```

## Tests

```bash
uv run pytest
```

```bash
cd web && npm test
```

All tests run offline from small fixtures in `tests/fixtures/`.

## Data and privacy

The data is the State of Oklahoma's public purchase-card file from data.ok.gov. The policy is
the OMES P-Card procedures and FAQ (the $5,000 limit is set by 74 O.S. § 85.5a). Cardholder
names are hashed with a private salt the moment they're read and never stored. Downloaded files
stay in `data/`, which is never committed. A flag means a purchase is worth reviewing. It is not
an accusation against anyone.
